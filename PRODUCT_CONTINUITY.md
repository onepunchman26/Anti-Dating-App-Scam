# Product continuity / 产品连续性

## English

The owner's October 21 instruction is persistent: entry points may change; the purpose
and agreed core capabilities remain. The original repository is authoritative. Read this
map before another feature or migration, then read the relevant source specification.
This is a requirement map, not a declaration that the whole product is accepted.

| Required capability | Original authority and current implementation | Current gap / acceptance |
|---|---|---|

| Evolving understanding with evidence, uncertainty and correction | docs/13, 17–29, 32; work_profile, relationship_interview, retained personal_model/report services | Current web has approved statements and a provisional interview draft. Legacy full-report/import tools remain available; not all have web equivalents. Never call tags a complete personal model. |

| Ordinary-user setup and truthful delivery | SETUP_WITH_CODEX.md, CURRENT_STATUS.md | v0.8.4 public download/install/reuse and local browser verified. Fresh accounts, general runtime eligibility and project licensing remain unresolved. |

Earlier documents sometimes call the old PySide interface, offline inference, no discovery
or plugin-only entry mandatory. Those implementation restrictions are superseded by the
owner's adopted web/local-companion, approved-summary Site and friends/groups directions.
Their requirements about real people, non-manipulation, evidence, editable uncertainty,
user choice and local private data remain binding. Old reports are historical evidence,
not permission to restore obsolete defaults. No founder answers become user defaults.

Before marking a change complete: identify its original purpose; connect the actual user
action to the reused service; check failure/correction/withdrawal; validate the installed
artifact and browser when changed; separately record independent-account and device gates.
Do not replace remaining work with a new framework or claim success from code generation.

Re-read evidence for this iteration: AGENTS, approved plan/status/progress, original vision,
architecture, trust ladder/scam taxonomy, safety/data governance, compatibility/criteria
design, conversation/reflection/standards correction, adult introductions, and current
plugin support/reflection/direction references. Dated implementation details are checked
against code. The earlier Desktop attachment is no longer present at its supplied path;
its already-adopted repository specification is retained, without inventing unseen text.
Unrelated untracked work and private vaults are not part of this audit.

部分旧文档仍把PySide界面、离线推理、禁止发现或插件唯一入口写成必需。这些实现限制已被本人后来
采纳的网页／本机助手、获准摘要网站和好友群组方向替代；真实人际关系、不操控、证据、可纠正的
不确定性、自主选择和本机私人资料等要求仍有效。旧记录是历史证据，不用于恢复过时默认设置，
也不能把创始人的答案设为用户默认值。

完成一项变化前：明确原始用途，把真实用户操作接到复用服务，验证失败／纠正／撤回，修改安装包或
网页时验证实际产物，单独记录独立账号及设备限制。不能用新框架替代剩余工作，不能以生成代码当作成功。

本轮重读依据：AGENTS、已批准计划／状态／进度、原愿景、架构、信任阶梯／诈骗分类、安全／资料治理、
相处适合度与择偶访谈、对话／复盘／规范整改、成年人介绍，以及当前插件支持／复盘／人生方向参考。
带日期的实现记录与代码核对。此前桌面附件在所给路径已不存在，保留仓库中已采纳的规范，不虚构缺失
正文。无关未跟踪工作和私人档案库不属于本次审计。
