# Criteria Discovery Interview (Stated vs Revealed Preferences)

Agent-facing technical detail. English-only per the bilingual rule in `AGENTS.md`.
Owner request 2026-07-06: after importing user data and building the self-portrait,
the AI must run an **intelligent interactive Q&A**, then generate **realistic (not
cinematic) ideal-partner profiles for the user to choose from**, so their actual
mate-selection criteria can be identified for more accurate matching. Hard
constraint from the owner: the AI must **not conform to the user's views** — it must
stay objective, even incisive.

## Why choices, not questionnaires

Stated preferences are unreliable: people report socially desirable criteria and
idealized packages ("ambitious AND always available"). Revealed preferences —
what someone actually picks when options have *costs* — predict real selection far
better. So the pipeline is:

1. **Interview** (interactive, in the agent chat): gap-driven, contradiction-
   probing, forced trade-offs, concrete episodes over abstractions.
2. **Choice exercise**: 5–7 synthetic partner *vignettes*, each with genuine flaws
   and trade-offs, **no Pareto-superior option** (if one candidate dominates, the
   exercise measures nothing). One "control" candidate literalizes the user's
   stated ideal *including its real-world costs*; one "counter" candidate
   contradicts a stated-but-suspect preference. The user ranks top 3 + one
   must-reject, with reasons.
3. **Synthesis**: stated vs revealed table, contradictions named plainly,
   criteria sorted into deal-breakers / strong preferences / actually-flexible,
   and a realism check on the package as a whole.

## Anti-sycophancy contract

The stance is written into `CRITERIA_INTERVIEW_REQUEST.md` itself (generated by
`apps/desktop_pyqt/anti_dating_scam_desktop/agent_handoff.py::
build_criteria_interview_request`), not left to the agent's mood:

- do not mirror the user's self-image; evidence over agreement;
- name conflicts between answers, data, and choices directly;
- no flattery; unrealistic criteria-packages are called out with reasoning;
- **incisive about criteria, kind to the person** — challenge the standard, never
  demean the user; no sarcasm, no diagnosis, no "you'll never find anyone";
- safety boundaries hold: no scoring of real persons, no gendered blame,
  everything stays in the vault.

## Data-saving standard

| Artifact | Location | Content |
|---|---|---|
| Interview transcript | `imports/interview/criteria_interview_transcript.md` | verbatim Q&A (user data → imports) |
| Candidate profiles + choices | `reports/ideal_partner_profiles.json` | synthetic vignettes, rankings, reasons |
| User-facing synthesis | `reports/mate_criteria.md` | bilingual; stated-vs-revealed, contradictions, sorted criteria, realism check |
| Structured synthesis | `reports/mate_criteria.json` | bilingual `{en,zh}` fields; feeds the Tier-1/Tier-2 compatibility card (docs/11) and matching |

## Where it sits in the product

Self-portrait (understand who you are) → **criteria interview (understand what you
actually select for)** → compatibility card (docs/11) → rendezvous discovery
(docs/12). GUI: Home → "Discover Your Real Criteria" prepares the request + prompt
(`CriteriaInterviewScreen`); results render in `CriteriaViewerScreen`.
